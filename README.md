# DYN-200: C++ клиент для ПК

Небольшой C++17/CMake-проект для стенда DYN-200 через Cyphal/CAN FD и Linux SocketCAN. Чтение скорости и момента и отправка команды тормоза показаны напрямую через libcxxcanard и DSDL `Real32`, без клиентской обёртки. Единственный собственный заголовок [`vbdrive.hpp`](include/voltbro_testbench_client/vbdrive.hpp) оставлен для испытаний отдельного мотора VBDRIVE. На стенде используется прошивка `DYN200TestBench` с узлом, обычно имеющим ID `79`.

## Сборка

Нужны CMake 3.22+, компилятор C++17 и Linux SocketCAN. Мост [VBCores/ethernet-can](https://github.com/VBCores/ethernet-can) создаёт отдельные интерфейсы: по требованию заказчика контроллер DYN-200 подключён к `vcan2.0`, а моторная линия VBDRIVE назначена на `vcan1.0`; возможные другие моторные линии — `vcan3.0`–`vcan6.0`.

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
```

CMake загружает `VBCores/libcxxcanard` на закреплённом коммите `6a8483b0271beeacda954b62de2c70e83d8f7fe3`. Прошивки могут использовать другие коммиты этой библиотеки. Для сборки без сети укажите `-DVTC_LIBCXXCANARD_SOURCE_DIR=/path/to/libcxxcanard`. Готовые DSDL-заголовки включены в репозиторий. Чтобы перегенерировать их, нужен `nnvg`; команда — `tools/generate_dsdl.sh`.

## Примеры

У всех примеров параметры находятся в начале исходного файла. Аргументы командной строки не нужны.

| Файл | Что показывает |
| --- | --- |
| [`examples/read_dyn200_raw.cpp`](examples/read_dyn200_raw.cpp) | Минимальная подписка на скорость и момент напрямую через libcxxcanard; вывод до Ctrl+C |
| [`examples/send_brake_5103.cpp`](examples/send_brake_5103.cpp) | Напрямую отправляет в `5103` значения `0` и `0,5` по очереди раз в секунду; Ctrl+C отправляет `0` |
| [`examples/try_mit_motor.cpp`](examples/try_mit_motor.cpp) | Пятисекундная MIT-проба мотора `0 1 0 0 0.5`, затем нулевая команда и попытка `is_on=0` |
| [`examples/try_servo_motor.cpp`](examples/try_servo_motor.cpp) | Двухсекундная Servo-проба `1 рад/с` с контролем телеметрии, нулевой скоростью и попыткой `is_on=0` |

Начните с `./build/read_dyn200_raw`. `send_brake_5103` отправляет физические команды тормоза: перед запуском проверьте механику и аварийный останов. Пример чередует `0` и `0,5`; при штатном Ctrl+C отправляет `0`, но после аварийного завершения выход может сохранить последнее значение. `try_mit_motor` и `try_servo_motor` приводят мотор в движение и требуют контроля оператора. Скорость и момент DYN-200 публикуются независимо и не образуют синхронную пару.

`./build/read_dyn200_raw` — минимальный вариант без заголовков клиента: он использует API libcxxcanard и DSDL-тип `Real32`, печатает сообщения портов `5100` и `5101` от node `79` и работает до Ctrl+C. Интерфейс, локальный node ID и ID стенда задаются константами в начале файла.

Схема для приложений без API клиента, DSDL-типы, идентификаторы портов и особенности тормоза описаны в [`docs/raw_libcxxcanard_dyn200.md`](docs/raw_libcxxcanard_dyn200.md).

`try_mit_motor` специально оставлен минимальным и не анализирует телеметрию. Он ожидает ответы регистра `is_on`; если ответ о выключении не пришёл, фактическое состояние привода остаётся неизвестным. При аварийном завершении процесса или потере связи программное выключение не гарантировано; держите доступным аппаратное отключение питания.

Историческая проверка 30.09.2026 проводилась при прежней схеме: мотор публиковал телеметрию на `vcan2.0`, а DYN-200 сначала не выдавал измерений на `vcan1.0`; его UART `status` показал `decimal_point valid=no`. Прямое чтение параметра `0x08` датчика вернуло масштаб `2`; после UART-команды `dyn stream start` публикация восстановилась. При ручном вращении за 10 секунд получено 193 отсчёта скорости (`0..565` об/мин) и 192 отсчёта момента (`−0,66..+0,69` Н·м). Скорость в этой пробе оставалась неотрицательной при вращении в обе стороны: не определяйте направление только по её знаку. Порядок действий при отсутствии потока — в [диагностике](docs/troubleshooting.md).

В установленной ранее версии прошивки VBDRIVE разработчик подтвердил баг повторного включения: вскоре после `is_on=0` следующая запись `is_on=1` может не сработать. Пауза **10 секунд после подтверждённого выключения** помогала в большинстве случаев, но не гарантировала успех. В последних прогонах оператор сообщил, что `is_on=0` не успевает подтвердиться в ожидании примеров. Оба примера отправляют команду выключения, но при отсутствии подтверждения выводят предупреждение и завершаются с ошибкой; считать мотор выключенным по отправке команды нельзя. Причина отсутствия подтверждения пока не установлена. Проверьте фактическое состояние привода и после подтверждённого выключения выдержите паузу перед повторным включением.

## Подключение к своему приложению

Для DYN-200 используйте [два примера на libcxxcanard и DSDL `Real32`](docs/raw_libcxxcanard_dyn200.md). Они линкуются напрямую с `libcxxcanard` и не используют наши заголовки. Для локальных испытаний VBDRIVE доступен один заголовок `include/voltbro_testbench_client/vbdrive.hpp`; моторные примеры линкуются с интерфейсной целью `voltbro_testbench_client`. Порядок сборки и подключения указан в [инструкции](docs/build_and_install.md).

## Протокол и ограничения

| ID | Тип | Значение |
| --- | --- | --- |
| 5100 | `uavcan.primitive.scalar.Real32.1.0` | Скорость DYN-200, об/мин |
| 5101 | `uavcan.primitive.scalar.Real32.1.0` | Момент DYN-200, Н·м |
| 5103 | `uavcan.primitive.scalar.Real32.1.0` | Команда тормоза, число от 0 до 1 |
| 7509, 7510 | стандартные типы Cyphal | Heartbeat и список портов |
| сервис 430 | `uavcan.node.GetInfo.1.0` | Информация об узле |

Скорость и момент появляются только после того, как прошивка прочитала масштаб момента с датчика. Если датчик включили позднее контроллера, выполните `dyn stream start` в последовательной консоли прошивки или перезапустите контроллер. Настройка частоты, обнуление и диагностика DYN-200 также доступны через эту консоль, а не через Cyphal. Подробнее: [`docs/dyn200_protocol.md`](docs/dyn200_protocol.md).

Команда тормоза удерживается прошивкой до следующей команды; автоматического тайм-аута нет. При завершении управления отправляйте `Real32` со значением `0` на `5103` и учитывайте, что при потере связи этот сброс может не дойти. Проверка получения команды возможна через последовательную консоль стенда.

VBDRIVE — отдельный узел и протокол: на subject `3811` он публикует `voltbro.foc.State.1.0` с меткой времени, положением (рад), скоростью (рад/с) и моментом (Н·м), обычно с периодом 1 мс. По прежней схеме на `vcan2.0` наблюдался узел `4`; после переноса на `vcan1.0` проверьте ID на месте. Управление использует `MIT.1.0` (`2107 + ID мотора`), `Servo.1.0` (`3407 + ID мотора`) и регистр включения `is_on` через сервис `384`. В прежних испытаниях MIT-команда `0 1 0 0 0.5` удерживалась 5 секунд: средняя скорость была `0,852 рад/с`, изменение положения `+4,267 рад`; после нулевой MIT-команды тогда подтвердилось `is_on=0`. Servo-проба с `+0,02 рад/с` была прервана примерно через `0,1 с` из-за колебаний скорости до `±2,2 рад/с`. Последующая Servo-проба с `+1 рад/с` прошла полные 2 секунды и дала изменение положения `+1,907 рад`, но скорость колебалась от `−1,35` до `+3,24 рад/с`. После неё тогда подтвердилось `is_on=0`. Остальные режимы `Servo` не проверялись. Подробности и источник протокола: [`docs/vbdrive_protocol.md`](docs/vbdrive_protocol.md).
