# DYN-200: C++ клиент для ПК

Небольшой C++17/CMake-проект для стенда DYN-200 и отдельного мотора VBDRIVE через Cyphal/CAN FD и Linux SocketCAN. Примеры для стенда используют только libcxxcanard и сгенерированный DSDL-тип `Real32`. Для испытаний мотора оставлен один собственный заголовок [`vbdrive.hpp`](include/voltbro_testbench_client/vbdrive.hpp).

Текущая схема: DYN-200 на `vcan2.0` (обычно node ID `79`), мотор на `vcan1.0` (ID проверьте на месте). Интерфейсы создаёт мост [ethernet-can](https://github.com/VBCores/ethernet-can). Локальный node ID ПК в примерах — `101`; он должен быть свободен на выбранной линии.

## Сборка

Нужны Linux, CMake 3.22+ и компилятор C++17.

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
```

CMake загружает закреплённый коммит `VBCores/libcxxcanard`. Для сборки без сети укажите `-DVTC_LIBCXXCANARD_SOURCE_DIR=/path/to/libcxxcanard`. Сгенерированные DSDL-заголовки уже включены в проект.

## Примеры

| Файл | Назначение |
| --- | --- |
| [`read_dyn200_raw.cpp`](examples/read_dyn200_raw.cpp) | Читает скорость `5100` (об/мин) и момент `5101` (Н·м) от DYN-200 через libcxxcanard и `Real32` |
| [`send_brake_5103.cpp`](examples/send_brake_5103.cpp) | Раз в секунду чередует команды тормоза `0` и `0,5` на subject `5103` |
| [`try_mit_motor.cpp`](examples/try_mit_motor.cpp) | Отправляет мотору MIT-команду `0 1 0 0 0.5` на 5 секунд |
| [`try_servo_motor.cpp`](examples/try_servo_motor.cpp) | Отправляет мотору Servo-команду скорости `1 рад/с` на 2 секунды и следит за телеметрией |

Примеры не принимают аргументы: интерфейс и ID меняйте в начале `.cpp`. Для пассивной проверки стенда запустите `./build/read_dyn200_raw`. Скорость и момент приходят независимо; направление вращения нельзя надёжно определить по знаку скорости.

**Команды меняют состояние оборудования.** Тормоз удерживает последнюю уставку без тайм-аута; `send_brake_5103` посылает ноль по Ctrl+C или SIGTERM, но аварийное завершение не гарантирует сброс. Моторные примеры отправляют нулевую уставку и запрашивают `is_on=0`; в последних прогонах подтверждение выключения не приходило за 500 мс. Пока состояние привода не проверено отдельно, не считайте его выключенным и не начинайте новую пробу. После подтверждённого выключения выдержите 10 секунд перед повторным включением из-за известной проблемы прошивки.
