# DYN-200: C++ клиент для ПК

Небольшая библиотека C++17/CMake для стенда DYN-200 через Cyphal/CAN FD и Linux SocketCAN. Она читает скорость и момент, отправляет команду тормозу и отдельно поддерживает телеметрию/команды VBDRIVE. На стенде используется прошивка `DYN200TestBench` с узлом `79`.

## Сборка

Нужны CMake 3.22+, компилятор C++17 и Linux SocketCAN. Мост [VBCores/ethernet-can](https://github.com/VBCores/ethernet-can) создаёт отдельные интерфейсы: контроллер DYN-200 находится на `vcan1.0`, моторные линии — `vcan2.0`–`vcan6.0`. Сейчас VBDRIVE подключён к `vcan2.0`.

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
```

CMake загружает `VBCores/libcxxcanard` на закреплённом коммите `6a8483b0271beeacda954b62de2c70e83d8f7fe3`. Прошивки могут использовать другие коммиты этой библиотеки. Для сборки без сети укажите `-DVTC_LIBCXXCANARD_SOURCE_DIR=/path/to/libcxxcanard`. Готовые DSDL-заголовки включены в репозиторий. Чтобы перегенерировать их, нужен `nnvg`; команда — `tools/generate_dsdl.sh`.

## Примеры

У всех примеров параметры находятся в начале исходного файла. Аргументы командной строки не нужны.

| Файл | Что показывает |
| --- | --- |
| [`examples/read_dyn200.cpp`](examples/read_dyn200.cpp) | Подписка на скорость и момент, вывод в консоль 10 секунд |
| [`examples/log_dyn200_csv.cpp`](examples/log_dyn200_csv.cpp) | Те же данные в `dyn200.csv` |
| [`examples/set_brake.cpp`](examples/set_brake.cpp) | Команда тормоза на 2 секунды с последующим сбросом в ноль; уставка по умолчанию 0 |
| [`examples/read_motor.cpp`](examples/read_motor.cpp) | Пассивная телеметрия VBDRIVE |
| [`examples/try_enable_motor.cpp`](examples/try_enable_motor.cpp) | Краткое включение уже выключенного мотора, выключение и пауза 10 секунд |
| [`examples/spin_motor_slow.cpp`](examples/spin_motor_slow.cpp) | Осторожная 10-секундная проба скорости 0,02 рад/с; требует явно заданных безопасных лимитов тока и момента |
| [`examples/try_mit_motor.cpp`](examples/try_mit_motor.cpp) | Минимальный пример: `is_on=1`, MIT `0 1 0 0 0.5` на 5 секунд, нулевая MIT-команда, `is_on=0`, пауза 10 секунд |
| [`examples/try_servo_motor.cpp`](examples/try_servo_motor.cpp) | Двухсекундная проба Servo VELOCITY `1 рад/с` (`servo_cmd: 0 1`) с контролем телеметрии, выключением и паузой 10 секунд |

Начните с `./build/read_dyn200`. Перед запуском `./build/set_brake`, `./build/try_enable_motor`, `./build/spin_motor_slow`, `./build/try_mit_motor` или `./build/try_servo_motor` проверьте нагрузку: эти примеры управляют физическим оборудованием. `try_enable_motor` ничего не меняет, если `is_on` уже равен 1 или не читается. `spin_motor_slow` по умолчанию не отправляет уставку, пока `max_spd`, `max_i` и `max_tq` не имеют конечных значений и не проходят консервативную проверку. На текущем моторе эти три регистра равны `NaN`; разовый тест с разрешённым оператором обходом проверки был прерван по телеметрии, после чего отправлена нулевая уставка и оператор обесточил мотор. Позднее MIT-проба с точными параметрами `0 1 0 0 0.5` прошла успешно; см. ниже. Скорость и момент DYN-200 публикуются независимо, поэтому строки CSV нельзя считать синхронными парами.

`try_mit_motor` специально оставлен минимальным и не анализирует телеметрию. Он подтверждает ответы `is_on`, но при аварийном завершении процесса или потере связи программное выключение не гарантировано; держите доступным аппаратное отключение питания.

При проверке 30.09.2026 мотор публиковал телеметрию на `vcan2.0`, но DYN-200 сначала не выдавал измерений на `vcan1.0`: его UART `status` показал `decimal_point valid=no`. Прямое чтение параметра `0x08` датчика вернуло масштаб `2`; после UART-команды `dyn stream start` публикация восстановилась. При ручном вращении за 10 секунд получено 193 отсчёта скорости (`0..565` об/мин) и 192 отсчёта момента (`−0,66..+0,69` Н·м). Скорость в этой пробе оставалась неотрицательной при вращении в обе стороны: не определяйте направление только по её знаку. Порядок действий при отсутствии потока — в [диагностике](docs/troubleshooting.md).

В установленной версии прошивки VBDRIVE разработчик подтвердил баг повторного включения: вскоре после `is_on=0` следующая запись `is_on=1` может не сработать. Пауза **10 секунд после подтверждённого выключения** помогает в большинстве случаев, но не гарантирует успех. Поэтому примеры не оставляют мотор включённым: они печатают сообщение о паузе, ждут 10 секунд и только затем завершаются. Если программа прервана раньше или выключение не подтверждено, выждите 10 секунд после фактического `is_on=0` самостоятельно; не повторяйте включение в быстром цикле. При отказе проверьте возвращённое значение `is_on` и состояние мотора.

## Подключение к своему приложению

```cmake
add_subdirectory(path/to/pc_cyphal_client)
target_link_libraries(your_app PRIVATE voltbro_testbench_client)
```

```cpp
#include <voltbro_testbench_client/dyn200.hpp>
#include <iostream>

int main() {
    using namespace voltbro::testbench;
    auto bus = makeCyphalInterface("vcan1.0", 101);  // ID ПК не должен совпадать с другими узлами.
    Dyn200Client dyn200(bus);                         // По умолчанию слушает узел 79.
    dyn200.onTorque([](const Dyn200Measurement& sample) {
        std::cout << sample.value << " Н·м\n";
    });
    while (true) bus->loop();
}
```

Колбэки вызываются внутри `bus->loop()`. Для контроллера стенда и тормоза на `vcan1.0` используйте один `bus`. Для каждого подключённого мотора создайте отдельный `bus` с соответствующим интерфейсом `vcan2.0`–`vcan6.0` и обрабатывайте его цикл. При частой телеметрии VBDRIVE выделяйте каждой активной линии свой поток обработки. После установки библиотеку можно подключить через `find_package(voltbro_testbench_client CONFIG REQUIRED)` и `voltbro::voltbro_testbench_client`.

## Протокол и ограничения

| ID | Тип | Значение |
| --- | --- | --- |
| 5100 | `uavcan.primitive.scalar.Real32.1.0` | Скорость DYN-200, об/мин |
| 5101 | `uavcan.primitive.scalar.Real32.1.0` | Момент DYN-200, Н·м |
| 5103 | `uavcan.primitive.scalar.Real32.1.0` | Команда тормоза, число от 0 до 1 |
| 7509, 7510 | стандартные типы Cyphal | Heartbeat и список портов |
| сервис 430 | `uavcan.node.GetInfo.1.0` | Информация об узле |

Скорость и момент появляются только после того, как прошивка прочитала масштаб момента с датчика. Если датчик включили позднее контроллера, выполните `dyn stream start` в последовательной консоли прошивки или перезапустите контроллер. Настройка частоты, обнуление и диагностика DYN-200 также доступны через эту консоль, а не через Cyphal. Подробнее: [`docs/dyn200_protocol.md`](docs/dyn200_protocol.md).

Команда тормоза удерживается прошивкой до следующей команды; автоматического тайм-аута нет. Вызывайте `BrakeClient::disable()` при завершении управления. Проверка получения команды возможна через последовательную консоль стенда.

VBDRIVE — отдельный узел и протокол: на subject `3811` он публикует `voltbro.foc.State.1.0` с меткой времени, положением (рад), скоростью (рад/с) и моментом (Н·м), обычно с периодом 1 мс. На текущей `vcan2.0` наблюдался узел `4`, но его ID на других линиях может быть другим. Управление использует `MIT.1.0` (`2107 + ID мотора`), `Servo.1.0` (`3407 + ID мотора`) и регистр включения `is_on` через сервис `384`. На живом оборудовании MIT-команда `0 1 0 0 0.5` удерживалась 5 секунд: средняя скорость была `0,852 рад/с`, изменение положения `+4,267 рад`; после нулевой MIT-команды подтверждено `is_on=0`. Servo-проба с `+0,02 рад/с` была прервана примерно через `0,1 с` из-за колебаний скорости до `±2,2 рад/с`. Последующая Servo-проба с `+1 рад/с` прошла полные 2 секунды и дала изменение положения `+1,907 рад`, но скорость колебалась от `−1,35` до `+3,24 рад/с`. После неё подтверждено `is_on=0`. Остальные режимы `Servo` не проверялись. Подробности и источник протокола: [`docs/vbdrive_protocol.md`](docs/vbdrive_protocol.md).
