# Стартовые сведения для агентов

Этот репозиторий — небольшой C++17/CMake-клиент для стенда DYN-200 и отдельного моторного контроллера VBDRIVE через Cyphal/CAN FD. Пользовательские инструкции и актуальный обзор — в `README.md`; протоколы подробно описаны в `docs/dyn200_protocol.md` и `docs/vbdrive_protocol.md`. Не предполагайте, что интерфейсы или ID устройств останутся такими же в другой установке.

## Источники истины и структура

- Прошивка стенда: соседний репозиторий `../../torque_testbench/DYN200TestBench`, прежде всего `App/cyphal_app.cpp` и `App/cyphal_app.h`.
- Прошивка мотора и текущие регистры: [VBCores/VBDrive](https://github.com/VBCores/VBDrive#fdcan-cyphal-runtime-interface). Её новый `State.1.0` **не** содержит ток/напряжение/температуры/ошибку.
- Клиентские заголовки: `include/voltbro_testbench_client/`; самостоятельные примеры: `examples/`. Готовые DSDL-заголовки: `generated/c` и `generated/cpp`; исходные Voltbro DSDL: `dsdl/voltbro_types`.
- `VBCores/libcxxcanard` загружается CMake на закреплённом коммите `6a8483b0271beeacda954b62de2c70e83d8f7fe3`; при работе без сети укажите `VTC_LIBCXXCANARD_SOURCE_DIR`.

## Текущая установка и протокол

| Линия | Устройство | Cyphal-порты и единицы |
| --- | --- | --- |
| `vcan1.0` | Контроллер DYN-200, обычно node ID `79` | `5100` скорость, Real32 об/мин; `5101` момент, Real32 Н·м; `5103` команда тормоза, Real32 от 0 до 1 |
| `vcan2.0` | Сейчас подключён VBDRIVE; при живой проверке node ID `4` | `3811` — `voltbro.foc.State.1.0`: время устройства, положение рад, скорость рад/с, момент Н·м |
| `vcan3.0`–`vcan6.0` | Возможные другие моторные линии; в последней проверке трафика не было | Уточняйте активную линию и ID узла на месте; `vcan6.0` — максимальный физический номер |

Мотор принимает `voltbro.foc.MIT.1.0` на `2107 + node_id` и `voltbro.foc.Servo.1.0` на `3407 + node_id` (режимы: скорость 0, момент 1, положение 2, напряжение 3). Включение — битовый регистр `is_on` через сервис `uavcan.register.Access` ID `384`. Старые имена `state.is_on`, `state_simple`, `specific_control`, `command` не используйте как текущий API. Ток, напряжение и температуры доступны через отдельные регистры, не через `State`; `is_fault` в установленной прошивке всегда возвращает `false` и не годится для диагностики неисправностей.

Для DYN-200 скорость и момент — независимые сообщения, не синхронная пара. Они появляются после чтения прошивкой десятичного масштаба датчика. Команда тормоза удерживается без тайм-аута до следующей команды; ноль отключает выход. У мотора телеметрия обычно идёт около 1 кГц. Мост [VBCores/ethernet-can](https://github.com/VBCores/ethernet-can) создаёт SocketCAN-интерфейсы; этот проект не реализует его UDP-протокол.

## Сборка и безопасная проверка

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
./build/read_dyn200
./build/read_motor
```

Примеры не разбирают аргументы командной строки: меняйте константы интерфейса/ID в начале `.cpp`. Локальный node ID ПК (`101` в примерах) должен быть свободен на выбранной линии. `read_dyn200` и `read_motor` только читают; `log_dyn200_csv` пишет файл в текущий каталог. `set_brake` отправляет физическую команду, хотя его уставка по умолчанию равна нулю. `try_enable_motor` сначала читает `is_on`, не трогает уже включённый привод, а после собственного включения пытается его выключить. Ненулевой тормоз, включение мотора и моторные уставки требуют осознанной проверки механики и разрешения пользователя; не используйте их для простого теста связи. После аварийного завершения процесса автоматического сброса тормоза нет.

Установленная прошивка мотора сообщает `firmware_rev=8dcb1274fd54361e`. Разработчик подтвердил её внутренний баг: после `is_on=0` повторное `is_on=1` иногда не срабатывает (ответ регистра остаётся 0). Оператор установил, что пауза 10 секунд после выключения помогает в большинстве случаев, но не гарантирует успех. Поэтому `try_mit_motor`, `try_enable_motor` и `try_servo_motor` после подтверждённого выключения печатают сообщение, ждут 10 секунд и только затем завершаются. Не оставляйте мотор включённым ради обхода бага; после прерывания программы или неподтверждённого выключения паузу нужно выдержать вручную. Не считайте ответ `is_on=1` доказательством движения: это подтверждается только телеметрией.

Проверка потоков 29.09.2026: `read_dyn200` получал скорость и момент на `vcan1.0`, `read_motor` — поток `3811` с `vcan2.0`. При повторной проверке 30.09.2026 `read_motor` получил 10 007 сообщений за 10 секунд, а DYN-200 сначала не публиковал `5100`/`5101`: UART `status` показал `decimal_point valid=no`. Параметр `0x08` датчика успешно прочитан со значением `2`; после UART `dyn stream start` поток восстановился. Ручное вращение за 10 секунд дало 193 отсчёта скорости (`0..565` об/мин) и 192 отсчёта момента (`−0,66..+0,69` Н·м); скорость оставалась неотрицательной при вращении в обе стороны, момент менял знак. Во время моторной проверки 30.09.2026 три пятитисекундные MIT-пробы дали вращение, затем повторное включение перестало подтверждаться; остальные моторные команды, кроме описанной ниже пробы Servo-скорости, не проверялись. При изменении прошивки сначала сверяйте DSDL и обработчики в исходниках, затем обновляйте клиент, примеры и документацию вместе.

Оператор запросил MIT `pos=0, vel=1, torq=0, p_gain=0, v_gain=0,5` на 5 секунд. Прежний диагностический вариант примера отправил команду на subject 2111: средняя скорость `0,852` рад/с, изменение положения `+4,267` рад за 5 011 отсчётов; затем отправил нулевой MIT и получил подтверждение `is_on=0`. Текущий `try_mit_motor.cpp` упрощён до последовательности команд и не собирает телеметрию. Эта команда работает на текущем узле, но её нельзя автоматически переносить на другую механику.

Servo-проба `try_servo_motor.cpp` с `+0,02` рад/с была рассчитана на 2 секунды, но прервана примерно через `0,1 с` по порогу колебаний: скорость `−2,218..+2,239` рад/с при почти неизменном положении (`−0,0069` рад). Нулевая уставка отправлена, `is_on=0` подтверждено. Считанные коэффициенты: `servo_vel_p_gain=30`, `servo_vel_i_gain=60`. Не считайте Servo-управление проверенным до настройки регулятора.

Позднее оператор явно разрешил двухсекундную пробу `servo_cmd: 0 1` при тех же P=30/I=60 и незаданных пользовательских лимитах. `try_servo_motor.cpp` отправил `Servo VELOCITY=1 рад/с`: положение выросло на `+1,907 рад`, но скорость по 202 полученным отсчётам была нерегулярной (`−1,348..+3,238 рад/с`, СКО `1,409 рад/с`). Нулевая скорость отправлена и `is_on=0` подтверждено. `try_servo_motor.cpp` теперь содержит эту уставку и не должен запускаться без присмотра.
